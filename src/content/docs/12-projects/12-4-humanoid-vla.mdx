## 프로젝트 개요

이 프로젝트는 **GR00T N1.7의 공개 추론·파인튜닝 경로를 확인한 뒤 사용자 로봇으로 확장**합니다. 최초 목표는 저장된 DROID 관측에서 예측 행동을 얻는 것입니다. 이후 시뮬레이션에서 수집한 시연을 변환하고 폐루프 조작을 평가합니다. 조작 성공을 휴머노이드 보행·전신 안정성의 검증으로 대신하지 않습니다.

```text
공개 샘플 추론 → 데이터/행동 해석 검사
                        │
                        ▼
시뮬레이션 시연 → GR00T 데이터 변환 → 파인튜닝
                                        │
                                        ▼
                          폐루프 시뮬레이션 → 실물 단계적 검증
```

## 환경과 버전

| 작업 | 환경 |
|---|---|
| GR00T N1.7 | 공식 저장소 commit + Python 3.12 + 해당 lockfile |
| 기존 시연 수집 예제 | Isaac Lab 2.3.2 + Sim 5.1 + Python 3.11 |
| 새 Isaac Lab 3.0 프로젝트 | Python 3.12 + 선택한 백엔드, 별도 마이그레이션 |

Sim 5.1은 지원 종료된 재현 환경입니다. 신규 시뮬레이션 프로젝트는 3.0/Sim 6.2 경로를 검토하고 아래 2.x 수집 명령을 그대로 혼용하지 않습니다. GR00T와 시뮬레이터는 파일 또는 명시적인 클라이언트 인터페이스로 연결하며 하나의 Python 환경에 의존성을 무리하게 합치지 않습니다.

## 단계 1: 공개 샘플 추론

[GR00T 챕터](../../09-foundation-vla/9-3-isaac-groot/)의 설치·모델 접근 승인을 완료한 후 Isaac-GR00T 저장소 루트에서 실행합니다.

```bash
uv run python scripts/deployment/standalone_inference_script.py \
  --model-path nvidia/GR00T-N1.7-3B \
  --dataset-path demo_data/droid_sample \
  --embodiment-tag OXE_DROID_RELATIVE_EEF_RELATIVE_JOINT \
  --traj-ids 1 2 \
  --inference-mode pytorch \
  --execution-horizon 8
```

성공 기준은 모델·정규화 설정·데이터를 로드하고 유한한 행동 청크를 얻는 것입니다. 기록된 정답 행동과 비교하되, 이 오픈 루프 평가만으로 물체를 실제로 집을 수 있다고 결론내리지 않습니다.

## 단계 2: 시뮬레이션 시연 수집

Isaac Lab **2.3.2 저장소 루트**에서 다음 명령으로 상대 EE 제어를 연습합니다. 일반 `teleop_se3_agent.py`는 조작 도구이며 데이터 저장을 자동으로 수행하는 명령이 아닙니다.

```bash
./isaaclab.sh -p scripts/environments/teleoperation/teleop_se3_agent.py \
  --task Isaac-Lift-Cube-Franka-IK-Rel-v0 \
  --teleop_device keyboard \
  --num_envs 1
```

기록에는 별도 `record_demos.py`를 사용합니다.

```bash
./isaaclab.sh -p scripts/tools/record_demos.py \
  --task Isaac-Lift-Cube-Franka-IK-Rel-v0 \
  --teleop_device keyboard \
  --dataset_file ./datasets/franka_lift.hdf5 \
  --num_demos 10
```

10개는 저장 경로를 검사하기 위한 예시입니다. VLA용 RGB 관측은 **태스크의 카메라·기록 설정과 `--enable_cameras`를 추가로 구성**해야 합니다. 기본 저차원 Lift 기록에 wrist 이미지가 자동 포함된다고 가정하지 않습니다. 언어 지시, 카메라 시각, 실제 적용 행동, 성공 판정도 저장합니다.

## 단계 3: 포맷과 행동 공간 변환

HDF5는 파일 컨테이너이지 GR00T 입력 스키마가 아닙니다. GR00T 참조 구현은 **LeRobot v2 계열 + `meta/modality.json`**을 요구합니다. LeRobot v3·OpenVLA RLDS와도 구분합니다.

변환기는 프로젝트에서 구현해야 하며 이 저장소에 완성된 범용 변환기가 있는 것은 아닙니다. 다음 계약을 맞춘 뒤 원본과 변환 결과를 에피소드별로 비교합니다.

| 계약 | 검증 기준 |
|---|---|
| 비디오 | 카메라 키, RGB 순서, 해상도, fps와 타임스탬프 |
| 상태 | 관절·EE 필드, 차원, 단위, 로컬/월드 프레임 |
| 행동 | 상대/절대 EE 표현, 그리퍼 범위, 청크의 시간 간격 |
| 메타데이터 | 에피소드 경계, 언어 지시, 통계, modality 매핑 |
| 분할 | 같은 시연을 학습·검증에 중복 포함하지 않음 |

Franka에서 얻은 관절 명령을 다른 휴머노이드의 관절에 직접 복사하지 않습니다. EE 행동을 새 제어기의 IK·관절 한계와 연결하고 필요한 시연으로 적응시킵니다.

## 단계 4: 공식 사용자 로봇 파인튜닝

먼저 GR00T 저장소의 공개 SO100 데이터와 modality 설정으로 경로를 확인합니다. 아래는 공식 예제의 단일 GPU 구성을 바탕으로 한 로컬 smoke test입니다.

```bash
CUDA_VISIBLE_DEVICES=0 uv run python gr00t/experiment/launch_finetune.py \
  --base-model-path nvidia/GR00T-N1.7-3B \
  --dataset-path ./demo_data/cube_to_bowl_5 \
  --embodiment-tag NEW_EMBODIMENT \
  --modality-config-path examples/SO100/so100_config.py \
  --num-gpus 1 \
  --output-dir ./outputs/so100_smoke \
  --save-total-limit 1 \
  --save-steps 20 \
  --max-steps 20 \
  --global-batch-size 2 \
  --dataloader-num-workers 0
```

20스텝은 학습 품질을 확보하는 레시피가 아닙니다. 체크포인트 저장과 데이터 배치·손실 계산을 확인한 후 공식 학습 설정으로 늘립니다. 새 로봇을 학습할 때는 SO100 데이터 경로·modality 설정을 함께 교체하고 `--help`로 사용한 commit의 인자를 확인합니다.

OpenVLA·openpi는 별도 대안입니다. GR00T 스크립트에 모델 ID만 바꾸는 방식으로 전환하지 않습니다. 각 프로젝트의 이미지 전처리·행동 정규화·학습 손실을 유지합니다.

## 단계 5: 폐루프 시뮬레이션 통합

GR00T는 GPU 정책 서버와 관측/행동 클라이언트 경로를 제공합니다. 시뮬레이터 어댑터는 현재 RGB·상태·언어를 계약대로 전달하고, 반환된 EE 행동을 로봇 제어기로 변환합니다. 아래는 구현해야 할 흐름이며 완성된 ROS 노드가 아닙니다.

```text
센서 시간 정렬 → 정책 서버 요청 → 행동 청크 수신
        → 만료·유한값·한계 검사 → 짧은 구간 실행
        → 새 관측으로 다시 계획
```

`vla_deploy`·`eval/run_vla_eval.py` 같은 가상 패키지를 실행하는 명령으로 대체하지 않습니다. 자체 어댑터의 관측 누락·네트워크 지연·언어 변경·비상 정지를 시뮬레이션에서 검사합니다.

## 결과 검증

처음 보는 초기 위치·물체·언어를 별도로 평가합니다. 성공/시도 수, 실패 유형, 충돌, 전체 태스크 시간, 통신 포함 지연을 기록합니다. 언어를 바꾸면 행동이 실제로 달라지는지도 검사합니다.

실물 이전에는 관측 정규화·좌표계·그리퍼 범위·행동 청크 실행 길이를 대조합니다. 이 프로젝트의 결과는 해당 로봇·환경·과제에 한정되며, 범용 가정 작업이나 전신 휴머노이드 제어 성능으로 확대 해석하지 않습니다.
